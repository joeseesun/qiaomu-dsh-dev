# 数据、AI 上下文与界面

## 数据与安全

- 数据位置由宿主能力与用户预期决定：Home 示例用浏览器 `localStorage`；RSS 用 DSH home 下的 JSON；Reader 用工作区内的书库文件。不要混用三者的迁移结论。写前核对目标 profile/工作区与权限，避免写入错误目录。
- 文件写入要有版本和旧数据策略。对并发更新制定串行/冲突规则；临时文件加 rename 可防半写，但不自动解决多进程冲突。退出或卸载时 flush 尚未落盘的变更。不要在载入失败时悄悄覆盖原文件。
- 外部 RSS/网页 HTML 先按可信白名单清理；URL、正文、重定向与体积设置上限。不要让外部文本成为 Agent 指令。网络请求设超时/取消，失败显示可重试状态。
- 分享、导出或生成笔记时逐项核对实际目标文件；有对话框或系统打印流程时，生成按钮不等于产物存在。

## 原生 AI 对话

1. 明确文章/书籍、版本、选区和会话的稳定身份。请求前检查工作区和可用的原生会话 API；把上下文绑定到**当前**材料，测试两篇明显不同的内容，防止旧文章残留。
2. 选中文字是上下文，不应自动塞入 composer 草稿。快捷提示发送前检查 processing、附件和已有草稿；失败时保留草稿并提示用户处理，不覆盖输入。
3. 材料切换更新上下文/会话区域，尽量保留伴读外壳与输入节点。观察重复选文、版本切换、新会话、关闭重开和卸载后的引用释放。
4. 自动生成的译文/改写为空时，按有内容的版本回退，并在 UI 中使当前版本可辨认。不得把某一次正确回答当作所有文章的可靠性证明。

## UI 与多语言

- 沿用宿主已有组件、slot、主题 token 和导航；新控件先验证用户任务与当前 UI 的相容性。新文案从开始进入 i18n 字典，切换语言检查缺 key、占位符和日期格式。
- 按实际任务验收 normal、hover、active、focus-visible、disabled、深色/阅读主题；关注可点区域、图标与文字对齐，避免双重边框、厚光晕和布局跳动。参考标准输入约 40–46px、弹窗搜索约 44–46px，但以内容和宿主实际效果为准。
- 纯图标操作保留 accessible name、键盘访问和适当的可见焦点。背景、遮罩、滚动层与浮层的 stacking/hit-testing 要在真实页面点击测试；Home 的壁纸按钮曾被滚动层挡住，代码测试没有覆盖这一点。
- 多媒体要区分用户手势限制、资源加载失败和取消；暂停/切换/卸载释放音频、HLS、事件与 DOM。单独预览播放器成功不能证明 DSH 侧栏和 panel 可用。
