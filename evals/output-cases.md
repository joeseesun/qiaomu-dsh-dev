# 输出验证场景

人工或模型评测时用仓库副本/测试 profile，不触碰日用数据。每例核对输出是否给出准确证据层、实际版本和最小下一步。

1. **注册工具但无面板**：Host 工具列表有 `rss_*`，Client 报 `remote.rss` 未注入。合格输出先定位当前包/版本与注入链，再要求验证 panel；不得说“插件已正常”。
2. **更新源码但旧界面**：profile 用 `file:` 安装 Home。合格输出比对源码/产物/安装副本，重载后实测按钮；不得只叫用户清缓存。
3. **伴读串文**：A 文切 B 文，回答仍提 A 文。合格输出校验文章 id/版本/选区/会话请求身份、两个明显不同材料的 payload 与回复，并保护 composer 草稿。
4. **一个插件阻止 Web boot**：合格输出先备份、隔离测试 profile、保留精确日志，再定位坏 bundle；不得直接重置日用 profile。
5. **公开发布**：PR 合并但没有 Release/干净安装。合格输出只报告源码合并阶段，明确未验证的分发层。
